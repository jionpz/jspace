# design — harness-config global 技能获取路径（#37）

## 现状与约束

| 事实 | 位置 |
| --- | --- |
| `manifest.global` 运行时零引用；install 只遍历 workbench | `cli/commands/skills.ts:49` |
| `installSkills` 按 `skills/<name>/` 前缀从 ASSETS 取内容（deps 注入，纯函数） | `application/skills/install.ts:46` |
| gen-assets 只把 `manifest.workbench` 目录加入 SOURCES 走单一 `ASSETS` map | `scripts/gen-assets.ts:33-48` |
| `materializedRels` 对任何 `skills/…` key 一律映射到 `.jspace/skills/…` + 各 harness 投影 | `application/workspace/manifest.ts:40-47` |
| `materializeTree` 对 rels 为空的 key 抛 `unexpected asset key`（filehub 前缀提前跳过） | `cli/embed.ts:98-102` |
| doctor `checkSkills` 不感知机器级技能；`SkillsDeps` 只有 workbench 视角 | `application/diagnostics/checks/skills.ts`、`application/diagnostics/deps.ts` |
| `install_source` 仅被测试读取；语义实为安装目标 | `cli/assets-reachability.test.ts:85-87` |
| upgrade 刷新 `~/.agents/skills/`（refresh 模式）只传 workbench 名单 | `cli/commands/workspace.ts:34-35` |
| doctor deps 在 cli 侧组装 | `cli/commands/helpers.ts:77` |

**硬约束**：harness-config 绝不能进入任何工作台物化路径（`.jspace/skills/`、`.claude/skills/` 等投影）——这是 manifest `scope: global` 与 AGENTS.md 记载的产品意图。

## 方案：独立生成模块 `GLOBAL_SKILLS`

### 1. gen-assets 产出 `cli/global-skills.generated.ts`

- 遍历 `skillsManifest.global` 声明的目录（存在性断言同 workbench：缺目录即抛错），walk 进**第二个 map**，emit：

  ```ts
  // generated by scripts/gen-assets.ts — do not edit by hand.
  import type { ... } // 不需要；纯 Record
  export const GLOBAL_SKILLS: Record<string, string> = { "skills/harness-config/SKILL.md": "…", … };
  ```

- key 保持仓库相对路径形 `skills/<name>/<rel>`（与 ASSETS 同形），使 reachability 测试的 `resolve()` 可直接复用。
- `renderAgentsBlocks` 维持只传 workbench 名单（global 技能不进工作台 AGENTS.md Brain-operations 块）。
- workbench 侧不变式不受影响：SOURCES、DistributionManifestV1、ownership、manifest.json twin 均不含 global 条目。

### 2. 安装：`skills install` 覆盖 workbench + global

- `cli/commands/skills.ts` `installHandler`：`names = [...workbench, ...global].map(s => s.name)`。
- deps 注入改为并集视图，`application/skills/install.ts` **零改动**（它只按前缀过滤 + 精确 key 取内容）：

  ```ts
  assetKeys: () => [...Object.keys(ASSETS), ...Object.keys(GLOBAL_SKILLS)],
  assetContent: (k) => ASSETS[k] ?? GLOBAL_SKILLS[k],
  ```

- 输出行照旧（`summarizeInstall` 不区分 scope；global 条目自然出现在列表里）。
- `--dry-run` / fill-gaps / `--refresh` 语义自动继承。

### 3. upgrade 通道一致

- `cli/commands/workspace.ts:34-35`：名单同样取 workbench + global，deps 并集同上。upgrade 对 `~/.agents/skills/harness-config` 的行为与其他官方技能完全一致（unchanged → skip；differs → refresh；missing → create）。

### 4. doctor `skills.global_missing`（info）

- `SkillsDeps` 增加可选注入（省略时检查静默跳过，与 `bundleStaleSkills` 同模式）：

  ```ts
  globalSkills?: () => Array<{ name: string; installPath: string }>;
  ```

- `application/diagnostics/checks/skills.ts` 新增检查块：对每个条目，`installPath` 经 tilde 展开后目录不存在 → `severity: "info"`, `code: "skills.global_missing"`, `path: "skills.<name>"`, message 指向 `jspace skills install`。
- cli 组装点 `cli/commands/helpers.ts:77` 附近注入：`SKILLS_MANIFEST.global.map(s => ({ name: s.name, installPath: s.install_path }))`，tilde 展开复用 `expandTilde`。
- 真实安装后目录存在 → 诊断消失（AC5 闭环）。

### 5. 契约更名 `install_source` → `install_path`

- `core/contracts/skills.ts`：`SkillEntry.install_path` + decoder 消息/约束同步（global 必填、workbench 禁用）。
- `skills-manifest.json` 字段更名；重跑 gen-assets 刷新 `cli/skills.generated.ts`。
- 读点仅 `cli/assets-reachability.test.ts:87`；skills-manifest.json 为 build-time 仓库数据，无用户数据迁移。

### 6. 文档（jspace-use）

- `skills/jspace-use/references/harnesses.md:3-4` 的循环获取措辞改为「由 `jspace skills install` 安装到 `~/.agents/skills/harness-config`」；各 `harness-<name>.md` 中同类表述一并核改（grep `Phase 1`/`自装` 定位，引用点共 13 处/7 文件，只改**获取方式**措辞，分工/不用条目不动）。
- harness-config 自身 SKILL.md 的 Phase 1 保留为无 CLI 场景兜底。
- 根 `AGENTS.md` 的 global 技能描述句已准确，可顺手补「由 skills install 安装」半句（C5 计数校验不受影响：名字清单与合计 8 不变）。

## 关键取舍：为什么不把 global 嵌进 `ASSETS`

| | 同前缀嵌 `ASSETS` | 独立 `GLOBAL_SKILLS`（选定） |
| --- | --- | --- |
| 不进工作台不变式 | 依赖 `materializedRels`/`materializeTree`/`diffBundle`/ownership 多点感知 scope，漏一处即泄漏 | 结构保证：物化机制只读 `ASSETS`，根本看不见 global 内容 |
| 触及面 | 改 4 处物化机制 + ownership 规则 | gen-assets 增一段 emit；物化机制零改动 |
| `materializeTree` 空 rels 抛错 | 需要新的 skip 分支 | 不触发（keys 不在 `ASSETS`） |
| 回归风险 | 中（物化/diff 是升级安全的核心路径） | 低 |

## 兼容与回滚

- 旧工作台：无任何变化（global 从不物化进工作台）；upgrade 后 `~/.agents/skills/harness-config` 出现属预期交付。
- 新生成文件 `cli/global-skills.generated.ts` 必须随源码提交（`git diff --exit-code cli/*.generated.ts` 门禁天然覆盖；它由 `cli/commands/skills.ts` import 进入编译 bundle）。
- 回滚：revert 提交 + 重跑 gen-assets 即可；唯一盘上产物是 `~/.agents/skills/harness-config/` 普通文件，无状态污染。
